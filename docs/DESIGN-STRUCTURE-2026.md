# DeepCompose 文件结构改造设计（2026-10，用户裁决确认稿）

本文是本轮改造的单一事实源。裁决记录见 `DECISIONS.md` D-043；既有 14 件套老作品**一个字不动**，新结构只对新建作品生效（老书可选「整理」动作，见 §8）。

## 0. 目标

1. 精简锁定资料构成：核心 7 件 + 细纲栏目 + 可选追踪模块；
2. 回流拆两路：资料回流（事实）/ 风格回流（表达），用户四态可选；
3. 格式与分类完全受限：AI 写入先过落点校验；
4. 资料表格化显示（只读视图，文件本体仍是 md）。

## 1. 新作品目录结构

```
<booksRoot>\<书名>\
├─ 小说资料\
│  ├─ 00-项目状态.md      状态入口（封闭头部字段 + 三个固定节）
│  ├─ 01-开书定位.md      向导七字段（格式不变）
│  ├─ 02-核心设定.md      三节（格式不变）
│  ├─ 03-全书大纲.md      全书走向（格式不变）
│  ├─ 04-粗纲.md          弧段级：## 第xx-xx章 弧段名 + 一段缩略内容
│  ├─ 06-写作风格.md      两节：风格规则（自然段）+ 禁用列表（- 禁止：…）
│  ├─ 人物库.md           ## 人物名 + 六方面自然段（格式不变）
│  ├─ 细纲\               栏目：第N-M章细纲.md（进行中/未启动/已完成）
│  ├─ 审核\               报告与归档（格式自由，无装饰纪律不变）
│  ├─ 个人改稿\           改稿对比-第N章.md + 规则台账.md（学习工作区）
│  └─ （可选模块，00 头部「启用模块」声明）
│     ├─ 追踪-伏笔.md / 追踪-角色状态.md / 追踪-时间线.md
│     └─ 追踪-资源与权限.md / 追踪-废弃设定.md
├─ 章节内容\第N章.md      正式正文（不变）
├─ 待确认\第N章-候选.md   唯一候选（不变）
└─ 待确认\已处理\         归档（不变）
```

旧名 `04-分卷大纲.md` / `05-滚动细纲.md` / `章节摘要.md` / `06-写作规则.md` 在新作品中不再创建；老作品照常工作（读取侧对两版结构都兼容，按盘上实际文件工作）。

## 2. 各文档固定格式

### 00-项目状态.md

封闭头部字段（顺序固定、字段一个不能少；应用按字段名读取）：

```
# 项目状态
- 项目名称：书名
- 当前阶段：开书准备 / 开书自检 / 连续写作 / 收尾
- 当前章节：第N章（待起草 / 起草中 / 待用户确认 / 回写进行中）
- 启用模块：角色状态、伏笔（只列启用的；全不启用写「无」；老作品无此行 = 按盘上实际文件为准）
- 最新正式正文：章节内容/第1章.md 至 第N章.md
- 当前细纲：细纲/第N-M章细纲.md（进行中）或 无
- 当前唯一最新候选：待确认/第N章-候选.md 或 无
- 正文处理进度：未开始 / 起草中 / 待逐段修改 / 修改复读中 / 待用户确认
- 本次必读：逐条相对路径
- 下一步：一句话
```

固定节：`## 开书自检`（状态/所检材料版本与范围/结论位置及未决项）、`## 最近一次采用回写`（来源章节与采用版本/回写状态/已更新文件/待完成项/尚未解决的冲突/最近更新时间）、`## 约定`（固定三行）。过程记录（校验、导入、迁移）一律放 `审核/`，不进 00。

### 04-粗纲.md

```
# 粗纲
## 第1-20章 弧段名
一段缩略内容（可短到一句话）。
```

只有「`## 第xx-xx章 弧段名` + 一段缩略内容」一种块；区间不重叠、按序；不写逐场细节；没设想的弧段不写。

### 细纲\第N-M章细纲.md

```
# 第N-M章细纲
- 状态：进行中 / 未启动 / 已完成
- 所属弧段：第N-M章（对应 04-粗纲 的条目）
- 覆盖范围：第N章至第M章

## 第N章 章名（可写「待定」）
承接与目标：……
主要场面：……
依据与约束：……
变化与章尾：……

## 第N+1章 ……

## 实际与细纲差异
（仅当采用稿偏离细纲时追加；没有就不写这节）
```

每份固定覆盖 3 章（临近结尾按实际剩余）；同一时刻最多一份「进行中」；弧段写完 = 文件改名 `第N-M章细纲（已完成）.md` + 状态行改「已完成」。**已完成细纲即章节摘要的替身**：起草第 N 章只读「上一段已完成细纲 + 当前细纲」，不再读全局摘要。

### 06-写作风格.md

```
# 写作风格
## 风格规则
（自然段：人称与视角、节奏、叙事距离、对话与描写偏好等本书特定要求）

## 禁用列表
- 禁止：……（一行一条；句式/用词/桥段；带来源：用户指定 / 学习沉淀·第N章）
```

只有两个节。通用写作纪律在 novel-writer 技能里，不进作品文件。

### 个人改稿\规则台账.md（新增，学习工作区）

```
# 规则台账
## GL-001
- 规则：一句话（删什么/改什么/禁什么）
- 类别：词汇 / 句法 / 标点 / 称谓 / 视角 / 节奏 / 其他
- 证据：第3章（「原」→「改」）；第7章（……）
- 命中章节数：2
- 状态：候选 / 已晋升 / 已否决
- 最近更新：YYYY-MM-DD
```

命中章节数 ≥2 即自动提请用户逐条确认（question）；确认 → 状态「已晋升」+ 进 06 禁用列表；否决 → 「已否决」留档。台账可被应用核对（与伏笔统计同手法）。

### 其余文档

01 / 02 / 03 / 人物库 / 五份追踪表 / 待确认 全部维持既有格式（只在新作品按清单决定**建不建**，建了的格式与旧版一致）。

## 3. 追踪模块的开书/中途两种进入

- **开书**：向导第三步「追踪模块」勾选（按类型给建议默认：言情=角色状态；悬疑=伏笔+时间线+角色状态；其余=角色状态；可改）。勾选的模块随 14→7 件套一起生成，`00` 头部写「启用模块」。
- **中途加入（建仓）**：工作台可发起「建仓」——AI 分段读全书（已完成细纲 + 摘要 + 按需回读正文），一次性重构出该追踪表到 `待确认/建仓-<模块名>-<日期>.md`，用户过目采用后落位并更新「启用模块」。动手前必须报预估 token 并经确认。
- **中途停用**：清单去掉该模块名，文件**不删**，AI 不再维护；启用与否都不影响老内容存在。

## 4. 回流分路 + 四态选择

- **资料回流**（事实层）：审稿 + 追踪表/摘要/状态增量回写（现有能力）。
- **风格回流**（表达层）：配对对照（editBase vs 最终稿，段落级 before→after 对齐）→ 候选规则进规则台账 → ≥2 章命中自动提请确认 → 进 06 禁用列表。
- 编辑器标题栏四态：**全部回流 / 仅资料回流 / 仅风格回流 / 不回流保存**；按书记住（manifest 字段 `reflowMode`，老书清单缺失则本次会话记住），默认「全部回流」。
  - 浮层**向下展开**（`.think-pop.down`）：这个 chip 贴在窗口顶部，向上开会被窗口上沿截掉（KL-UI-19 实测 214px 的浮层有 110px 在屏幕外）；输入区那枚思考档位 chip 贴在窗口底边，仍向上开。
- **采用门固定走「资料回流 + 风格对照」**（采用时手里有现成的 editBase↔最终稿对）。
- **轻改动（≤24 字符且数字未变）不再跳过**，走「仅风格」通道（低成本、不审稿）。
- **回流队列落盘**：入队即写 oplog（`reflow_pending`），完成写 `reflow`；打开作品时扫描未完成的 pending 并补跑。关窗不再丢回流。

## 5. 写入落点校验（B6）

`file_write` 写 `小说资料/` 下的文件时先过该文件的 schema：

- **结构硬拒**：人物库条目缺六方面、追踪表条目缺字段、00 头部缺字段、04 粗纲出现非弧段块、06 出现第三个节、正文/细纲出现表格或装饰符号 → 报错并把正确格式回给 AI 重写；
- **语义软警告**：人物库里写大段世界观叙述等"写错文件"嫌疑 → 写入成功但结果里带 `warning` 字段，并入回流报告；
- **例外**：AI 经 question 获用户批准后放行（本次会话内记住该文件的白名单）。

schema 定义一处真源（`store/docschema.ts`），三处共用：写入校验 / 表格视图 / 资料体检。

## 6. 表格视图（P1 只读）

- 编辑器标题栏「原文 / 表格」切换；追踪类文件默认表格、其余默认原文；选择按书记住（manifest 字段 `viewMode`）。
- 行/列映射见 §2 各文件格式；长单元格两行截断、点击展开；过窄退化为逐条卡片。
- **节级回落**：某条目解析失败 → 该条显示原文 + 顶部「第 N 条未按格式解析」提示（只报告不改写）。
- P2（以后）：单元格直接编辑 → 走同一写入管线（快照 + 节内替换 + 回流）。

> **2026-10-06 落地（D-046）**：全覆盖 —— `docTableFor` 不再返回 null，任何 md 都有视图（不认识的走
> 通用回落）；表格可手改（单元格编辑 / 加删行，行级手术复用既有保存管线）；展开判定改实测溢出。
>
> **2026-10-11 修订（D-061 / D-062 / D-063）**：
> - **切换钮按内容驱动**：`hasRealTable()`（有 grid 或 kv）才出现钮；纯散文文档（人物库、03-全书大纲）
>   不给钮 —— 点进去还是同一段话，属误导。视图**能力**仍全覆盖，收窄的只是**入口可见性**。
> - **列宽按表声明**：`COLUMN_WEIGHTS`（100 分制）→ `<colgroup>` + `table-layout:fixed`，
>   **只对用户点名的表启用**（规则台账 / 追踪-伏笔 / 章节摘要 / 06 规则表），
>   细纲、粗纲、00、01、02 保持内容自适应。列集必须完全一致，部分匹配整体放弃。
> - **grid 表去掉行末空列**：原 `.dt-rowact` 删钮列就是用户看到的"最右边多余空白列"，
>   删钮改悬停浮在行右端。
> - **状态值符号化**（只改显示层）：√ = 已达成 / ? = 开放·待观察·附条件 / × = 未达成·已否决·废弃。
>
> **2026-10-11 批 3 修订（D-067 / D-068）**：
> - **06「风格规则」表格化**：节内格式由自然段改为 `### SR-编号` + 三行字段
>   （规则分类 / 规则来源 / 具体内容），四列 grid 因此真实出现（`[10,15,10,65]`）。
>   **列名与字段名逐字相同** —— 这是刻意的：加行走通用 `buildEntryBlock`，它拿列名当字段名。
> - **新旧双认**：切不出 SR 块 → 「风格规则」整节回落散文卡，老书不迁移照旧读；
>   写入校验只约束 `SR-\d+` 块，自然段格式直接放行。
> - **06 默认表格视图**（与规则台账/追踪表同档），因为它现在与那些文件同构。
> - **一张文档可以有多张不同性质的 grid**：06 的规则表（固定四列）与禁用列表（自适应两列）并存。
>   所以「能不能加行」「要不要固定列宽」都必须**按表按列结构判**，不能按文件名一刀切
>   —— 首版按文件名放行，禁用列表也长出加行钮，被回归锁抓住（见 D-069 附注）。

## 7. 兼容与迁移

- 老作品一个字不动；新结构只对新建作品生效。
- 小熊书按用户裁决做试点转换（旧版原文压缩归档到 `.openwrite_backup/迁移-2026-10-05.zip`——`.` 前缀不进内容树、界面不留备份，zip 校验完整后才删可见目录）：
  ① 启用模块 = 伏笔 + 角色状态，时间线/资源与权限/废弃设定归档冻结；
  ② 章节摘要保留为「第1-40章历史索引」（首部加注），41 章起由已完成细纲接替；
  ③ 04→粗纲：未写章节（44-49）拆成未启动细纲文件（无损），已写章节（1-41）节拍删除（摘要/细纲已接替）。
