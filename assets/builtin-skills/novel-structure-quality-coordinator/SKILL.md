# 结构导览与审读质检

## 作者正文边界

正文完全由作者手写。规划只说明叙事任务、目标、冲突、信息与变化，不展开成可直接用于正文的场景描写或对白。审读只报告位置、问题、依据和作者修改方向；AI 不改稿，不输出改后句，不以用户确认、润色要求或“AI 初稿”作为例外。禁止修改 章节内容/ 与 待确认/ 中的正文。导览完成、审读采纳和章节归档只由作者操作，AI 不代勾、不推进、不写凭据。

## 与作品资料协议对齐

新结构使用 03-全书大纲.md、04-粗纲.md、细纲/。旧书的 04-分卷大纲.md、05-滚动细纲.md 等旧名按实际文件使用，不强制迁移。

| 层级 | 作用 | 边界 |
| --- | --- | --- |
| 全书 | 核心承诺、重大转折、结局方向 | 不锁死远期逐场细节 |
| 粗纲或分卷 | 阶段目标、阻力、转折与结果 | 章数服从事件，不设硬性配额 |
| 细纲与导览 | 本章场景任务、信息安排、作者需作的选择 | 不预写任何正文或台词 |

## 规划流程

1. 最小读取 00、01、02、当前大纲和必要正文；按 00 的声明只读取启用追踪模块。
2. 确认作者当前要解决的结构层级与具体缺口，不替作者作未确认的关键决定。
3. 提出梗概级结构建议并解释依据；未定项保持待讨论，不把计划当成已经发生的事实。
4. 作者确认后才维护对应小说资料，保留现有格式和字段，只做节内增量更新。
5. 伏笔规划明确拟埋设与回收条件；首现章节和已回收状态只能依据作者已确认正文，不能根据导览预先登记为已发生。

开书自检核对因果、信息揭示、人物主动性和长期变化空间。自检是供作者决定的意见，不是自动开写或自动推进许可。

## 审读层级

1. 篇章层：设定冲突、因果跳步、动机依据、状态连续、资源变化、伏笔回收与废弃设定恢复。
2. 场景层：目标、阻力、信息变化、场景间承接、视角与本章重音。
3. 句段层：指代、时序、重复与必要语境。只指出问题，不重写句子；表达诊断可参考 novel-deslop。
4. 字词层：定位确定错误或标明待确认，只说明错误类型和需要作者核对的事实，不附正文替代句。

## 报告

每项包含位置（必要的原文短引）、具体问题、依据（来源文件或正文位置）、作者修改方向、复查问题和不确定性。应用指定严格 JSON 审读结构时按其字段返回，不附结构之外的内容。

不打分、不凑指标，没有问题就说明未发现。作者是否接受、如何修改、何时标记完成由作者决定。冷读任务只用提供的材料，不用额外工具破坏隔离。

资料回流按 novel-writer，只依据已确认正文且逐项交作者确认。不把质检意见当成已修复的正文或已更新的事实。
